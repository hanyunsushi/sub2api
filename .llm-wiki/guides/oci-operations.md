# OCI Operations and Artifact Retention

The OCI runtime uses Compose project `sub2api-oci`. Replace only the `sub2api` application service with `docker compose -p sub2api-oci up -d --no-deps --wait --wait-timeout 150 sub2api`; PostgreSQL, Redis, and all formal data volumes stay in place.

Transfer a clean Git archive and reject `.DS_Store` and `._*` residues before building. Preserve archive modes when extracting under a restricted umask (`tar --no-same-owner -xpzf`). The Dockerfile sets the entrypoint mode with `COPY --chmod=755`; adding only execute bits to a 600 file leaves the nonroot runtime unable to read it. Verify the actual container mode, active/tag image IDs, and healthy state before declaring success. An explicit bounded health wait must capture failure logs and roll back on error.

On a host without BuildKit/buildx, adapt both `FROM --platform` and cache mounts, and replace `COPY --chmod=755` with `COPY` followed by `RUN chmod 755 /app/docker-entrypoint.sh`. Run the candidate with its default entrypoint and `-version`; overriding the entrypoint only verifies the binary and misses script permission failures. The runtime Compose file references `sub2api-custom:codex`: preserve its old image under a rollback tag, retag the verified candidate to `codex`, then recreate only the application. Confirm the resulting container uses the candidate image ID; an unchanged healthy old container does not establish activation.

For compatibility with already-open pages, merge retained hashed assets into `backend/internal/web/dist/assets` before compiling the Go `embed` binary, preserving current-build files on collisions. In `backend/internal/web/embed_on.go`, `FrontendServer.Middleware` checks the embedded filesystem before trying `data/public` overrides, so copying an old asset only into the data volume does not make a missing embedded path servable. Verify retained asset bytes over HTTP as well as on disk, and keep the current build's `index.html`.

Build from a clean committed archive, pass COMMIT/VERSION/DATE build arguments, verify the candidate binary with `-version`, then confirm the active container/tag image IDs. Capture the release rollback tag, old source, full database dump, app data archive, migration-source hashes and pre/post container mounts without publishing credentials. Integration checks must also verify saved secrets and unrelated provider configurations are preserved. Exact current release evidence is owned by the [Project Authority](../../agent.md).

Sub2API retains the active `sub2api-custom:codex` image plus exactly the three newest `sub2api-custom:codex-pre-*` rollback tags. Review the explicit OCI tag list and active image reference before deleting old tags. Keep backups and formal volumes; shared builder caches and other projects remain outside routine application release cleanup. Recheck rollback count, active/tag identity and health afterward.

## Large request upload triage

Correlate the client's request ID and timestamp with `http request completed` and `read request body failed` in OCI application logs. In `backend/internal/handler/request_body_read_log.go`, `requestBodyReadErrorKind` labels `io.ErrUnexpectedEOF` as `truncated_body`; this describes an incomplete incoming upload, rather than a model-generation timeout. The Responses handler reads the request body before upstream routing, so changing SSE keepalive or changing model accounts does not repair this stage.

Use bounded, authenticated synthetic uploads with an empty `model` to compare client proxy, a separately verified physical route, OCI loopback, and OCI public ingress. The expected result is a parameter-validation 400 after the complete body is received; verify that no model inference is dispatched. Use normal API authentication without logging credentials or content. A 25–40 second test timeout is an observation limit, not proof of a server timeout at that duration. Record payload length, bytes uploaded, negotiated HTTP version, request ID and elapsed time; HTTP 200 from a small health request does not establish upload throughput.

For 20 MB diagnostics, use an exact 20,000,000-byte random base64 JSON body without Content-Encoding, rather than compressible repeated text. Require the full client byte count, normal certificate verification, and the specific application response `model is required`; a generic 400 or curl exit 0 alone does not establish complete receipt. A 524 can arrive while the client has sent only part of the body. Correlate matching server request IDs where available, otherwise state the timestamp/length/order basis and its limits. Keep HTTP TTFB separate from model TTFT; an empty-model upload does not exercise inference or WebSocket transport.

A `--noproxy` test can still traverse a system TUN and fake-IP route. Confirm the actual routing interface and Mihomo connection chain; for isolated proxies verify selector changes through the controller before labeling a test by node. Repeat measurements before attributing a fault to a proxy node or calling a route stable. An application loopback pass cannot by itself prove the external network is healthy. For a physical-interface test with TUN still active, bind the interface and use the current public-DNS address while preserving Host/SNI and certificate validation; confirm the socket interface independently. An ordinary proxy-domain test can use a different cached destination, so record whether the proxy endpoint IP was actually observed. Current measurements and remaining scope are owned by the [Project Authority](../../agent.md#20mb-直连与代理复测2026-11-12).

When a public proxy upload fails, compare OCI direct egress, a temporary loopback client of the existing AnyTLS service, a physically bound independent client to its public port, and a separate SSH transport to the same host. A failure to an unrelated upload target plus retransmissions on the physical proxy TCP socket separates the ingress transport from AI model processing. Observe sustained transfers and individual connections: a short SSH upload can succeed while a later connection stalls. Retain exact byte/validation evidence, treat retransmission counts as transport symptoms rather than IP loss rates, and distinguish client deadlines from actual server 524 responses. A successful loopback test alone does not identify the public-network fault; matching public TCP evidence is required. Current segmented findings belong to the [Project Authority](../../agent.md#oci公网上传分段定位2026-11-12).

## OpenAI WebSocket upstream verification

Client `101` and `openai.websocket_ingress_started` confirm only the client-to-gateway WebSocket. To identify the actual gateway-to-upstream transport, correlate the ingress request/session with `ingress_ws_protocol_confirm` (account, transport, upstream host/path, mode), `ingress_ws_upstream_connected` (connection ID), and subsequent `ingress_ws_turn_chain` / `ingress_ws_next_turn_chain` on that connection. In `backend/internal/service/openai_ws_forwarder_ingress.go`, `ProxyResponsesWebSocketFromClient` logs these around upstream connection acquisition and continued response-ID chaining. Do not infer the upstream protocol from the incoming HTTP access-log protocol or the account switch alone; upstream aggregators' internal model connections remain outside this evidence.

Read only the account's WS mode/enabled fields, the running container's `GATEWAY_OPENAI_WS_*` values, and its persisted `gateway.openai_ws` section. If overrides are absent, inspect defaults from the exact deployed source. `mode_router_v2_enabled=false` uses legacy context-pool behavior; an account mode label does not prove v2 routing is active. Filter credentials and request content before returning diagnostic output; use an explicit read-only database transaction when account metadata is required.

An `ingress_ws_error_event` with `generate:false is not supported` after upstream connection establishment identifies an upstream rejection of a prewarm request. Check later normal turns before concluding all generation is broken. A client-first-message deadline before upstream acquisition is a separate ingress failure. Current production observations and remaining compatibility gaps are owned by the [Project Authority](../../agent.md#合聚上游-wss-只读核验2026-11-11).
