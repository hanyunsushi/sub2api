# Creeper & AI 站点知识库

本文件是 Creepee 的手动维护知识库。它面向站内用户、管理员和网页问答场景，只记录可公开解释的产品知识、功能说明、常见问题和排障思路。

内容参考 Sub2API 官方文档中的通用定位：Sub2API 是 AI API 网关平台，提供调用令牌分发、多账号管理、计费、调度、并发控制、速率限制、支付和管理后台能力。本站在此基础上做了 Creeper & AI 的定制，因此回答时以本站当前页面、菜单、渠道和配置方式为准。

本文件不记录管理员私密信息、后台连接值、本机文件路径、发布记录、容器信息、提交编号、内部账号值或任何不能公开给普通用户搜索的内容。管理员以后手动更新知识库时，也应保持这个边界。

## 站点是什么

Creeper & AI 是基于 Sub2API 定制的 AI API 网关和控制台。用户在站内创建调用令牌，用令牌访问管理员开放的模型入口；平台负责鉴权、路由、账号池调度、用量统计、计费、余额、订阅、渠道状态和请求转发。

对普通用户来说，本站主要解决这些问题：

- 创建和管理自己的调用令牌。
- 查看余额、用量、扣费、订阅和订单。
- 查看自己可用的渠道、模型和全局价格。
- 查看渠道状态、延迟、可用率和最近检测结果。
- 使用兑换码、充值、订阅和返佣功能。
- 在个人资料页管理账号、安全设置和通知设置。
- 使用侧边栏自定义页面和 Creepee 智能助手。

对管理员来说，本站主要解决这些问题：

- 管理用户、分组、账号池、渠道、模型价格和用量记录。
- 接入不同上游平台，并把入口模型映射到真实上游模型。
- 维护账号优先级、并发、调度、代理、健康状态、备注和标签。
- 配置渠道监控、请求模板、自定义探针和用户可见状态页。
- 配置站点主题、登录方式、支付、邮箱、公告、自定义菜单、AI logo、Cloudflare AI Search 和 R2 灾备。
- 管理 Codex / CPA 认证账户和相关元数据。

## Creepee 智能助手

Creepee 是站内右上角的智能助手入口。搜索框文案是 `Ask Creepee`，侧边栏标题是 `Creepee`，副标题是 `智能助手`。

点击入口后，Creepee 会以类似 Cloudflare 官方 AI 助手的侧边栏形式出现在页面右侧。这个侧边栏会挤压站内主界面，而不是简单浮在页面上方；只要还在站内切换路由，侧边栏应保持打开。

Creepee 的默认界面包含螃蟹头像、像素风动效、随时间变化的问候语和推荐问题。进入对话后，历史记录集成在左上角按钮里，避免历史列表长期占据聊天宽度。历史列表展开后，点击侧边栏外的空白区域应关闭历史列表。

Creepee 用来回答站内功能、配置和常见问题。它适合回答：

- 如何创建调用令牌。
- 为什么某个模型不可用。
- 渠道监控和连接测试为什么结果不同。
- 自定义菜单应该选 iframe 还是新标签页打开。
- 账号优先级、分组、调度和模型映射是什么意思。
- QLHazyCoder、TCDMX、Buzz 等外部订阅余额显示代表什么。
- R2 灾备保存什么、不保存什么。
- 知识库手动更新后为什么需要同步才会影响问答。

Creepee 不应回答后台连接值、真实管理员账号、私有运维路径、部署命令、生产镜像、提交编号或其它内部细节。遇到这类问题，应改为解释功能边界和安全原则。

## 知识库维护与同步

本知识库采用手动维护方式。管理员应直接维护这份公开知识 Markdown，而不是从内部运维文档自动抽取内容。

手动维护后的常规流程是：

1. 修改公开知识内容。
2. 检查是否混入管理员私密信息或内部运维细节。
3. 在后台 Cloudflare AI Search 设置中执行“立即同步知识库”。
4. 等待同步和索引完成后，再用 Creepee 提问验证。

如果管理员点击“立即同步知识库”后感觉 Creepee 没变化，常见原因有三个：

- 只改了本地文档，还没有同步到 Cloudflare AI Search。
- 同步接口返回成功，但 Cloudflare 侧索引仍需要一点时间完成。
- 后台配置了源文档路径，导致同步时读取了别的来源并覆盖手写内容。

为了保持手动维护，Cloudflare AI Search 的源文档路径应留空，知识文档路径应指向这份手写的用户知识文档。这样立即同步和定时同步都会上传手写文档，而不是重新生成一份公开知识。

## 用户页面

### 仪表盘

仪表盘展示账户概览、余额、可用分组、近期用量和常用入口。用户登录后通常先在这里确认自己是否有余额、订阅是否有效、分组是否正常。

右上角余额区域会轮播或展示多个余额来源。系统余额表示站内账户余额；外部订阅余额来自管理员配置的外部服务摘要，例如 Buzz、TCDMX、QLHazyCoder。外部订阅余额只用于展示，不等同于站内系统余额。

### 调用令牌

调用令牌页面用于创建、复制、禁用、删除和查看用户自己的调用令牌。用户在客户端、脚本、IDE 或模型工具中使用调用令牌访问本站模型入口。

调用令牌本身不决定所有模型权限。用户能否调用某个模型，还取决于用户分组、分组可见模型、渠道配置、账号池可用性、模型映射和价格策略。

如果调用失败，用户应先检查：

- 调用令牌是否启用。
- 余额或订阅是否足够。
- 当前分组是否允许目标模型。
- 渠道状态页是否显示对应渠道异常。
- 客户端填写的 Base URL 和模型名是否为本站入口模型。

### 用量统计

用量统计页面展示请求量、Token 消耗、模型分布、服务档位、费用、时间趋势和失败记录。用户对扣费有疑问时，应先查看这里的明细。

扣费由模型价格、分组倍率、服务档位、输入输出 Token、缓存读写、图片或特殊请求计费共同决定。全局价格页展示的是基础价格，实际扣费还会受到分组和用户配置影响。

### 可用渠道与渠道状态

可用渠道页面让用户查看自己当前能使用哪些渠道或模型入口。渠道状态页展示管理员发布的监控结果，包括可用性、延迟、主模型、附加模型和最近历史。

渠道状态不是完整的真实业务流量统计，它是定时探针结果。一个渠道状态正常，仍可能因为用户分组、余额、模型映射或特定请求体不同而在实际调用时失败。

### 订阅、充值、订单、兑换码与返佣

订阅页面展示用户已有订阅、有效期和配额。购买订阅页面用于选择可购买套餐。订单页面展示支付订单状态。兑换码页面用于使用管理员发放的兑换码。返佣页面用于查看邀请、奖励和转账记录。

这些入口是否可见，取决于管理员是否启用了对应功能和用户当前分组权限。没有入口时，通常表示站点当前没有开放该功能，或用户不在允许范围内。

### 个人资料

个人资料页面用于查看和修改账号信息、安全设置、身份绑定、头像、通知和邮箱相关选项。用户遇到登录、邮箱、双因素认证或通知问题时，应优先检查个人资料页。

## 管理后台

### 用户管理

用户管理用于查看用户、调整余额、修改角色、启用或禁用账号、绑定分组、查看注册来源、邀请关系和风险信息。

管理员调整用户权限后，用户实际可用模型可能会随分组变化而变化。如果用户反馈模型不可用，应同时检查用户状态、余额、分组、订阅和调用令牌状态。

### 分组管理

分组是权限、计费和账号池的核心。分组可以控制：

- 用户默认倍率和并发。
- 是否为订阅型分组。
- 日、周、月等配额限制。
- 可用渠道或账号池范围。
- 用户能看到和调用的模型。
- Claude Code、Codex 或其它特定链路的限制。

用户看到的模型入口通常来自分组和渠道配置，不一定等于上游平台原始模型名。

### 账号管理

账号管理用于接入真实上游账号或上游服务。账号可以来自 OAuth、会话授权、上游控制台配置、兼容平台账号或其它支持的接入方式。

账号卡片上会显示平台、类型、状态、分组、余额或额度摘要、模型信息、优先级、备注、标签和最近活动。账号列表支持按名称和优先级升降序排序。

账号勾选框左侧的 `P1`、`P10` 等标记表示账号优先级。优先级影响调度顺序：优先级更高的可用账号会更容易被选中；同优先级账号之间还会结合最近使用时间、并发、等待队列、健康状态和其它调度条件分散请求。

账号优先级不是用户分组本身的优先级。它是账号池内的调度参数，通常由管理员在账号管理中维护。

账号状态常见含义：

- 活跃：账号可参与调度。
- 失败：最近检测、刷新或调用出现问题，需要查看错误信息。
- 即将过期：账号状态接近失效，需要处理授权或额度。
- 已禁用：管理员手动关闭，不参与调度。
- 未知：暂时没有足够状态数据。

### 渠道管理与价格管理

渠道管理维护平台、入口模型、模型映射、倍率、定价、可见范围和上游模型同步。价格管理维护对用户展示和计费使用的模型价格。

入口模型是用户和客户端填写的模型名。上游模型是实际发送到上游平台的模型名。两者可以相同，也可以通过模型映射不同。

因此，排障时要分清：

- 用户请求的入口模型。
- 渠道配置中的模型。
- 账号卡片显示的模型。
- 最终发送给上游的模型。

这四个名字不一定完全一致。

### 渠道监控

渠道监控用于定时检测上游渠道是否可用。管理员可以配置监控名称、平台、协议模式、上游地址、主模型、附加模型、分组名称、检测间隔、自定义 AI logo、请求模板、自定义请求头和请求体处理方式。

当前渠道监控的供应商类型主要是 OpenAI、Anthropic 和 Gemini。OpenAI 协议下可以选择 Chat Completions 或 Responses API 模式。监控能测什么模型，不由 QLHazyCoder、TCDMX 或 Buzz 这些余额展示源决定，而由该监控的上游地址、协议模式、主模型、附加模型和实际渠道配置决定。

监控模型应优先填写本站对外暴露的入口模型。如果监控直接打到某个上游兼容地址，则应填写该上游实际支持的模型。不要只根据账号卡片上的来源名称判断监控模型。

渠道监控和连接测试不同。连接测试通常只验证后台连接是否能通；渠道监控会按设定的协议、模型、请求体和模板发起探针。连接测试通过但监控失败，常见原因包括：

- 连接测试和监控使用的 endpoint 不同。
- 监控填写的是上游模型名，但本站需要入口模型名。
- 账号池没有可调度账号。
- 请求模板、请求头或请求体不符合上游要求。
- 上游要求特定客户端指纹或特殊字段。
- 默认 challenge 校验没有拿到预期结果。
- 监控使用的协议模式与上游实际能力不一致。

### 渠道监控的 replace / 覆盖模式

渠道监控高级设置里的“请求体处理”有默认、合并和覆盖三种方式。这里的覆盖模式常被称作 replace。

默认模式会使用适配器默认请求体，并带 challenge 数学题校验。它适合确认模型确实按预期理解并返回内容，但有时会消耗更多 token，也可能被某些上游兼容实现误处理。

合并模式会把管理员填写的字段浅合并到默认请求体，但会保护 model、messages、contents 等核心字段。它适合只增加某些上游要求的参数。

覆盖模式会完全使用管理员填写的 JSON 请求体。覆盖模式跳过默认 challenge 校验，改为以 HTTP 2xx 和响应文本非空作为可用判断。它通常更省 token，适合做轻量可用性探针。

如果目标是让渠道监控尽量省 token，推荐在请求模板中使用覆盖模式，并写一个极短输出的探针请求。例如让模型只返回一个固定短词，或使用上游支持的最低输出配置。具体 JSON 要按所选协议和上游兼容格式填写。

`challenge mismatch (expected 58, got "")` 一般表示默认 challenge 校验没有收到预期答案。它不等于调用令牌坏了。排查顺序建议是：

1. 确认监控协议模式是否正确。
2. 确认主模型填写的是入口模型还是上游模型。
3. 确认 endpoint 是否是监控真正要访问的地址。
4. 检查账号池是否有可用账号。
5. 检查请求模板是否覆盖了必要字段。
6. 如果只是做可用性探针，改用覆盖模式降低 token 并绕开默认 challenge。

### 请求模板

请求模板是一组可复用的自定义请求头和请求体处理配置。把模板应用到监控时，会把模板内容复制成该监控自己的快照。模板后续变化不会自动同步到已经关联的监控，除非管理员手动执行“应用到关联监控”。

这意味着：如果多个渠道监控都要改成最省 token 的覆盖探针，最好维护一个通用模板，然后选择需要覆盖的监控并应用。应用模板会覆盖被选监控的相关快照，请操作前确认不会丢掉个别监控的特殊配置。

## Mimo、入口模型与上游模型

Mimo 相关问题最容易混淆的是“卡片显示”和“真实调用模型”。

账号卡片里写着 Mimo，通常表示该账号来源、平台或上游能力与 Mimo 有关。但用户调用或渠道监控应该填写什么模型，要看本站入口模型和模型映射。

例如，一个入口模型可能显示为 `gpt`，但经过模型映射后实际发往上游的模型是 `mimo-v2.5`。这种情况下，用户侧或监控侧看到 `gpt` 并不代表没有使用 Mimo；它可能只是本站对外暴露的入口名。

如果问题是“为什么 Mimo 时是 gpt，不应该是 mimo-v2.5 吗”，正确解释通常是：

- 账号卡片显示的是来源或上游相关信息。
- 调用入口可能使用站内统一模型名。
- 模型映射会把入口模型转换成上游模型。
- 监控和用户调用应优先使用站内入口模型。
- 需要确认最终上游模型时，应查看渠道配置、模型映射链或用量记录里的上游模型字段。

Mimo 流式响应中可能出现先返回空内容、再返回 reasoning、最后返回真实文本的形态。本站兼容层会处理这类流式片段，避免因为开头空内容导致最终回答丢失。

## QLHazyCoder、TCDMX、Buzz 和外部订阅

QLHazyCoder、TCDMX、Buzz 在本站主要用于外部订阅或余额摘要展示。它们显示在管理员右上角余额区域或余额下拉中，帮助管理员快速查看外部服务余额、额度或到期信息。

QLHazyCoder 展示读取的是 qlhazycoder New API 控制台相关余额、订阅额度和到期摘要。它不是一个固定的渠道监控模型清单。若某个 QLHazyCoder 渠道要被监控，应按该渠道的 OpenAI 兼容地址和实际支持模型来配置主模型与附加模型。

TCDMX 展示现在和其它余额项一样，只显示剩余额度，不显示总额。TCDMX 的余额展示也不等于模型调用能力，模型能力仍以渠道和账号配置为准。

BuzzAI 展示用于读取 Buzz 余额或订阅摘要。前端只展示状态、余额和到期摘要，不负责保存或暴露后台连接信息。

外部订阅余额和站内系统余额不同。外部余额可能说明某个上游服务还有额度，但用户能不能调用仍取决于站内用户余额、分组、调用令牌、账号池、渠道和模型映射。

## 自定义菜单

管理员可以在系统设置中增加自定义菜单。自定义菜单可以显示给用户，也可以只显示给管理员。

每个自定义菜单可以设置：

- 菜单名称。
- 目标 URL 或 Markdown 页面。
- 图标。
- 可见范围。
- 排序顺序。
- 打开方式。

打开方式有两种：

- `iframe`：在站内 `/custom/<id>` 页面嵌入目标地址。
- `redirect`：从侧边栏新开标签页打开目标链接。

如果目标网站禁止 iframe，被嵌入页面可能打不开、空白、跳登录或报安全限制。这不是本站一定出错，而是目标网站不允许被嵌入。遇到这种情况，应把打开方式改成 `redirect`，让它在新标签页打开。

Markdown 内置页面适合用 iframe 方式在站内展示。外部网站如果需要自己的登录态、跨站 cookie 或明确禁止嵌入，更适合用新标签页打开。

自定义菜单支持调整顺序。保存后，侧边栏会按新的排序展示。

自定义菜单图标支持内联 SVG，也支持 SVG 图床链接。使用 SVG 图床链接后，已登录用户可以把链接保存到服务端可选图标库，后续新增菜单时继续选择。

## 系统设置

系统设置覆盖站点级配置。常见区域包括：

- 站点名称、Logo、默认主题和显示设置。
- 登录、注册、邮箱、第三方登录和安全选项。
- 用户功能开关、支付、订阅、兑换码和返佣。
- Cloudflare AI Search 与 Creepee。
- S3 兼容对象存储和 R2 灾备。
- 自定义菜单、AI logo、图标预设和外部订阅展示。

设置项保存后，有些会立即影响前端显示，有些需要用户刷新页面或重新登录，有些会影响后台任务。管理员排障时应先确认设置是否保存成功，再确认前端是否加载了最新设置。

## Cloudflare AI Search

Cloudflare AI Search 用于保存 Creepee 可检索的知识索引。本站前端不直接访问 Cloudflare 后台接口，而是通过 Sub2API 后端代理搜索和聊天请求。

Cloudflare AI Search 的测试连接只说明搜索/聊天连接可以使用，不代表知识库内容一定是最新。知识库内容是否最新，需要看是否完成了知识库同步和索引。

立即同步知识库会尝试删除同名旧知识项和遗留旧项，再上传当前知识文档。同步成功后，Creepee 才有机会检索到新内容。

如果管理员希望以后完全手动维护，应保持公开知识 Markdown 为唯一内容来源，并避免重新启用从内部运维文档抽取公开知识的配置。

## R2 灾备

R2 灾备用于保存数据库备份和对象文件。它不是实时业务数据库，也不能直接接管全部数据。

本站业务状态主要保存在 PostgreSQL，包括用户、账号、分组、设置、用量、计费、订阅、订单、兑换码、Codex / CPA 元数据和其它结构化数据。

Redis 主要用于缓存、限流、队列和临时状态。Redis 不是主要长期数据源。

Cloudflare R2 适合保存备份文件。R2 访问方式不可用时，通常只是当前访问能力受影响，不代表已有对象被删除。管理员可以重新开通有权限的访问方式来访问已有对象。

用户问“R2 能不能替代数据库”时，答案是不能。R2 是对象存储，适合保存备份和文件；PostgreSQL 才是本站主要业务数据存储。

## Codex / CPA 管理

管理员后台提供 Codex / CPA 账号管理能力，用于管理 Codex 相关认证账户和运行元数据。

该页面可以查看账号状态、上传认证文件、删除文件账号、启停账号、打开 OAuth 授权、维护分组、备注、标签、显示名称和排序。

分组、备注、显示名称、标签、排序等管理元数据保存在 Sub2API 数据库中，因此同一管理员在不同浏览器登录后能看到一致配置。

真实认证文件、OAuth 流程、刷新状态和部分运行状态由 CPA / CLIProxyAPI 负责。失败账号卡片会展示 CPA 返回的错误码和错误文字，方便管理员定位授权、额度或上游问题。

Codex / CPA 管理只面向管理员。普通用户不需要知道真实认证文件细节，只需要知道自己可以通过站内调用令牌访问管理员开放的 Codex 或 Claude Code 兼容模型入口。

## 数据保存在哪里

站内数据大致分为几类：

- 源代码和公开文档：保存在代码仓库中。
- 用户、账号、分组、设置、用量、计费、订阅、订单和 Codex / CPA 元数据：保存在 PostgreSQL。
- 缓存、限流、队列和临时状态：主要使用 Redis。
- 数据库备份和对象文件：保存到 S3 兼容对象存储，例如 Cloudflare R2。
- Creepee 可检索知识索引：保存到 Cloudflare AI Search。

这些存储用途不同，不能互相简单替代。

## 常见问题

### Creepee 为什么答不上新内容？

先确认手写 Markdown 是否已经更新，再确认后台是否执行了“立即同步知识库”，最后等待 Cloudflare AI Search 完成索引。如果只改了文档但没有同步，Creepee 不会立刻知道新内容。

### 为什么连接测试通过，渠道监控却失败？

连接测试和渠道监控不是同一种请求。连接测试可能只验证基础连通性；渠道监控会按指定协议、模型、模板和请求体发起探针。模型名、endpoint、请求体、账号池、挑战校验或上游兼容行为不同，都可能导致监控失败。

### `challenge mismatch (expected 58, got "")` 是什么？

它表示默认 challenge 校验没有收到期望答案。常见原因是模型没有按预期返回短答案、上游返回空内容、请求体不兼容、模型名不对或上游兼容实现不支持这种探针。若只是做可用性监控，可以考虑用覆盖模式写极短探针，降低 token 并绕开默认 challenge。

### 所有渠道监控怎么做成最省 token？

使用请求模板，把请求体处理设为覆盖模式，并写一个极短输出的探针请求。然后把模板应用到需要调整的监控。应用前要确认个别监控没有必须保留的特殊请求头或请求体。

### QLHazyCoder 支持什么监控模型？

QLHazyCoder 在本站主要是外部订阅余额展示来源，不是固定监控模型表。若某个 QLHazyCoder 兼容渠道要做监控，应按该渠道 endpoint 实际支持的模型填写，优先使用站内配置的入口模型，必要时再看上游模型列表。

### Mimo 为什么有时看起来是 gpt？

因为站内入口模型和上游模型可以不同。入口模型可能叫 `gpt`，模型映射后真实上游模型可能是 `mimo-v2.5`。账号卡片显示 Mimo 只能说明来源或上游能力，不能单独决定用户或监控应该填什么模型。

### 账号分组是不是默认轮询？

不能简单理解成只有轮询。调度会先筛选可用分组和账号池，再结合账号启用状态、模型能力、优先级、并发、等待队列、最近使用时间和健康状态选择账号。同优先级账号之间会尽量分散使用；设置更高优先级后，该账号会更容易被优先选择。

### 账号卡片左侧的 P1、P10 是什么？

这是账号优先级。数值用于管理员识别和排序，也会参与调度。账号管理筛选栏可以按名称或优先级升降序排序。

### 为什么自定义菜单 iframe 打不开？

目标网站可能禁止被 iframe 嵌入，或需要跨站登录态、特殊 cookie、额外安全策略。把打开方式改成 `redirect` 后，侧边栏会在新标签页打开目标链接，通常能绕开嵌入限制。

### redirect 会把当前站点跳走吗？

不会。自定义菜单的 redirect 打开方式是从侧边栏新开标签页打开目标链接，不会直接把当前 Sub2API 控制台页跳走。

### SVG 图标链接能保存吗？

可以。自定义菜单图标支持 SVG 图床链接。使用后可以保存到服务端可选图标库，后续创建菜单时继续选择。

### R2 可以保存全部站点数据吗？

不能。R2 适合保存备份和对象文件。实时业务数据仍由 PostgreSQL 保存，缓存和临时状态由 Redis 保存。

### R2 访问方式不可用后数据还在吗？

通常还在。访问方式不可用只是当前连接方式不能使用，不代表已有对象被删除。管理员可以重新开通有权限的访问方式来访问已有备份。

### TCDMX 为什么只显示一个余额？

右上角系统余额中的 TCDMX 已按本站当前显示规则处理，只显示剩余额度，不显示总额。这样和其它余额来源保持一致。

### 知识库可以直接用内部运维文档吗？

不建议。内部运维文档包含发布流程、路径、状态记录和不适合公开搜索的细节。Creepee 应使用手动维护的公开知识库，只回答产品和功能层面的内容。
